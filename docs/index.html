Vortex Engine modding

Vortex Engine is built on Psych Engine 1.0, so Psych Lua and HScript mods keep working. On top of that it adds custom screens, reusable scripted objects and scripts for the built-in menus, so you can build bigger mods without touching the engine's Haxe source.

Everything on this page is implemented in the engine as it ships. Anything marked Psych works the same way as in Psych Engine, and the Psych Engine wiki has the full list of its standard Lua functions. Anything marked Vortex is new in Vortex Engine and documented in full here.

Setting up a mod

A mod is a folder inside mods/, next to VortexEngine.exe. Create a folder for your mod and add only the subfolders you need.

mods/ └─ My-Mod/ ├─ pack.json name, description, "runsGlobally", "hideBaseGameWeeks" ├─ weeks/ week files (optional, see below) ├─ data/<song>/ charts + song scripts ├─ songs/<song>/ Inst.ogg, Voices.ogg ... ├─ characters/ stages/ images/ sounds/ music/ ├─ scripts/ Lua/HScript that runs in every song ├─ custom_events/ your chart events ├─ custom_notetypes/ ├─ states/ Vortex: custom states + menu scripts (+ Global.lua) ├─ classes/ Vortex: scripted classes ├─ lib/ Vortex: shared Lua modules for require() ├─ achievements/ Vortex: <id>.json + .png icon + optional .lua script └─ data/keybinds.json Vortex: your mod's own rebindable keys
  • Mods are switched on and off in the Mods menu. A new folder is switched on automatically.
  • Songs without a week: a song that has a chart in data/<song>/ but isn't in any week file still shows up in Freeplay and Story Mode, in an automatic week named after the mod.
  • Vortex Hiding the base game's weeks: the base game (Tutorial to Weekend 1) ships with Vortex. A mod that replaces it can hide those weeks from Story Mode and Freeplay while it's switched on, with "hideBaseGameWeeks": true (all of them) or a list like "hideBaseGameWeeks": ["tutorial", "week1"] in its pack.json. Deleting files from the game's assets/ folder isn't a reliable way to do this (a rebuild copies them back).
  • When you start the game, Vortex writes vortex_mods_log.txt next to the exe. It lists every mod, whether it's on, how many songs, characters, stages and events it has, and whether each song's Inst file was found.

Where scripts go

Every script can be Lua (.lua) or HScript (.hx). Where you put the file decides when it runs.

Path in your modRuns
scripts/*.luaIn every songPsych
data/<song>/*.luaIn that song onlyPsych
stages/<stage>.luaWhen that stage is usedPsych
characters/<name>.luaWhen that character is in the songPsych
custom_events/<Event>.luaWhen the event is in the chart, or the first time a script fires itPsych Vortex
custom_notetypes/<Type>.luaWhen the chart uses that note type, or the first time spawnNote makes onePsych Vortex
states/<BuiltInState>.luaAlongside a built-in screen, e.g. states/MainMenuState.luaVortex
states/<YourState>.luaAs a whole screen, opened with switchState('YourState')Vortex
classes/<Class>.luaWhen you create an object from it with createScriptedVortex
states/Global.luaIn every menu and custom state, before that state's own scriptVortex
lib/<name>.luaNever by itself: other scripts load it with require('name')Vortex
achievements/<id>.luaIn every song, while that achievement is still lockedVortex
Which mod's files are used? In songs, it's the mod the song belongs to, plus any mods with "runsGlobally": true in their pack.json. For states/ and classes/, Vortex looks in every enabled mod (the current one first). That's because in menus only the top mod is "current".

Debugging

  • Vortex Every script error goes to vortex_script_log.txt next to the exe: Lua and HScript, in songs and menus. Lua errors include the file, the line and the full stack traceback: 
    23:38:29 [ERROR] Lua: mods/My-Mod/states/Gallery.lua (onUpdate)
  mods/My-Mod/states/Gallery.lua:59: attempt to index local 'broken' (a nil value)
  stack traceback:
  	mods/My-Mod/states/Gallery.lua:59: in function <mods/My-Mod/states/Gallery.lua:53>
  • Vortex A runtime error is also shown on screen once, in red. Psych only showed Lua errors with luaDebugMode on, so broken scripts failed silently. The same error is never repeated, so an error in onUpdate doesn't flood the screen or the log 60 times a second.
  • Put luaDebugMode = true at the top of a Lua script to print every occurrence of its errors, plus Psych's extra warnings.
  • debugPrint('text') shows a message on screen. It works everywhere: in songs, in menus and in custom states. Outside songs the messages appear top-left and fade after about 6 seconds.
  • Vortex writeToScriptLog('text') adds your own line to the log. getScriptErrorCount() tells you how many different errors happened this session.
  • Vortex Press F3 for the developer overlay. In a song it shows how many notes are on screen or waiting, how long the chart took to build, how many Lua and HScript scripts are running, and the script error count. F7 reloads the song and its scripts, and shows already-seen errors again.
  • If the game hits an error it can't handle, it goes back to the main menu and shows a red message instead of closing. Full details go to the crash/ folder next to the exe.

Lua API

All of Psych Engine 1.0's Lua functions are available and behave the same, including Psych's own createInstance and callMethod for Haxe classes. Vortex changes what's described below.

Lua now runs outside songs Vortex

In Psych, Lua scripts only exist during a song. In Vortex, the same Lua runs in menus, custom states and scripted classes. These functions work everywhere:

  • Sprites and text: makeLuaSprite, makeAnimatedLuaSprite, makeGraphic, addLuaSprite, removeLuaSprite, makeLuaText, addLuaText, setTextString, setTextColor, setTextSize and the others.
  • Properties: getProperty and setProperty, including the 'tag.scale.x' style.
  • Tweens, timers and sounds: doTweenX and friends, runTimer, playSound, playMusic. Their onTweenCompleted, onTimerCompleted and onSoundFinished callbacks reach the scripts of whatever screen is running.
  • Input: keyboardJustPressed, keyboardPressed, the gamepad functions and mouseClicked.
  • debugPrint, getModSetting.
  • Talking to other scripts: callOnScripts, callOnLuas, callOnHScript, setOnScripts, setOnLuas, setOnHScript, callScript, isRunning, addLuaScript, addHScript, removeLuaScript, getRunningScripts. Outside songs they reach the scripts of the current screen. In Psych they crashed the game there.
  • Controls: keyJustPressed, keyPressed and keyReleased work in menus too (they crashed there), and accept any bind name, including your mod's own key binds.
  • startTween with onUpdate / onStart / onComplete callbacks, and custom substates.

Song-only functions such as characterDance, setHealth or note functions still need a song. In a menu they fail with a script error (written to vortex_script_log.txt) instead of crashing the game.

addLuaSprite(tag, false) normally places the sprite behind the characters. Outside a song there are no characters, so the sprite is simply added on top.

New functions Vortex

Custom states, state switching and scripted classes each have their own section below. The function reference lists every new function in one table.

Custom states Vortex

A custom state is a whole screen made from one script, such as a gallery, a sound test, a cutscene menu or a minigame. Put it in states/<Name>.lua (or .hx) and open it from any script.

function onCreate()
    makeLuaSprite('bg', '', 0, 0)
    makeGraphic('bg', 1280, 720, '120C24')
    addLuaSprite('bg')

    makeLuaText('title', 'GALLERY', 1280, 0, 40)
    setTextSize('title', 40)
    addLuaText('title')

    local args = getStateArgs()          -- whatever switchState() passed
    debugPrint('opened with: ' .. tostring(args[1]))
end

function onUpdate(elapsed)
    if keyboardJustPressed('ESCAPE') then
        switchState('MainMenuState')     -- back to a built-in screen
    end
end

Open it from anywhere, whether a song script, an event, a menu script or another custom state:

switchState('Gallery')                         -- no arguments
switchState('Gallery', {'hello', 42})          -- arguments, read with getStateArgs()

Callbacks

FunctionWhen
onCreate()When the screen opens.
onCreatePost()On the first frame, after everything is created.
onUpdate(elapsed)Every frame, before the screen updates.
onUpdatePost(elapsed)Every frame, after the screen updates.
onDestroy()When leaving the screen.
onTimerCompleted, onTweenCompleted, onSoundFinishedSame as in songs.

Opening built-in screens

switchState also opens the engine's own screens by name: MainMenuState, FreeplayState, StoryMenuState, OptionsState, CreditsState, TitleState and ModsMenuState. If your mod has a custom state with the same name, yours is opened instead. Switching away from a song stops its music, like "Exit to menu" does.

If nothing has that name, switchState returns false, prints a message and stays on the current screen. It never leaves you on a black screen.

State scripts (scripting the built-in menus) Vortex

Give a script the name of a built-in screen and it runs alongside that screen. The screen keeps working normally, and your script can add things to it. This is how you add a way into your custom states.

function onCreatePost()
    makeLuaText('hint', 'Press G for the gallery', 600, 660, 660)
    addLuaText('hint')
end

function onUpdate(elapsed)
    if keyboardJustPressed('G') then
        switchState('Gallery')
    end
end

The callbacks are the same as for custom states. Use onCreatePost to draw on top of the screen's own graphics. The file name must match the screen's name, for example MainMenuState, FreeplayState, StoryMenuState, CreditsState or TitleState. Songs don't use this: during a song, use scripts/ or data/<song>/ as in Psych.

Scripted classes Vortex

A scripted class is a reusable object written once in classes/<Name>.lua (or .hx). You can create as many copies ("instances") of it as you want, in songs, menus or custom states. Each instance is a normal sprite saved under its tag, so every sprite function works on it.

-- "self" is the instance's tag, so use it like any sprite tag
local timeAlive = {}

function new(self, color)
    makeGraphic(self, 120, 120, color or 'FFFFFF')
    addLuaSprite(self, true)
    timeAlive[self] = 0
end

function update(self, elapsed)
    timeAlive[self] = timeAlive[self] + elapsed
    setProperty(self .. '.y', 300 + math.sin(timeAlive[self] * 3) * 60)
end

function jump(self, height)          -- your own method
    setProperty(self .. '.scale.x', 1.5)
    setProperty(self .. '.scale.y', 1.5)
    return 'jumped ' .. height
end

Use it from any script:

createScripted('Bouncer', 'red', 300, 300, 'FF4F7A')    -- class, tag, x, y, then up to 5 values for new()
createScripted('Bouncer', 'teal', 500, 300, '35D0C0')

local result = callScripted('teal', 'jump', 120)       -- call your own method, get its return value
setProperty('red.alpha', 0.5)                          -- instances are normal sprites

if scriptedExists('red') then destroyScripted('red') end

Class functions

All of these are optional. The instance always comes first. In Lua that's its tag; in HScript it's the sprite itself.

FunctionWhen
new(self, ...)When createScripted makes the instance. It receives the extra values you passed.
update(self, elapsed)Every frame.
beatHit(self, beat)Every beat, while music is driving the beat clock (in songs).
stepHit(self, step)Every step, under the same conditions.
destroy(self)When destroyScripted removes the instance.
any script callbackNew onBeatHit(self), goodNoteHit(self, ...), onEvent(self, ...), onKeyPress(self, key) and so on, plus your own callbacks sent with callOnScripts / callOnLuas. The class gets the same arguments as normal scripts, with self in front.
anything elseCalled with callScripted(tag, 'name', ...).
 
function new(self, size)
    makeGraphic(self, size or 20, size or 20, 'FF00FF')
    addLuaSprite(self)
end

function onBeatHit(self)            -- song / menu callbacks reach classes too
    setProperty(self .. '.angle', curBeat * 15)   -- curBeat, crochet... stay up to date in classes
end

function ping(self, value)          -- a custom callback: callOnScripts('ping', {5}) reaches every instance
    debugPrint(self .. ' got ' .. tostring(value))
end
  • Each class script is loaded once per screen and shared by all its instances. Lua variables at the top of the file are shared too, so store per-instance data in a table keyed by self, as above.
  • new doesn't add the sprite to the screen by itself. Call addLuaSprite(self, true) (Lua) or FlxG.state.add(self) (HScript) when you want it shown.
  • Instances are cleared when the screen changes. Removing one with removeLuaSprite(tag, true) also stops its update.

HScript class

function new(self, size) {
    self.makeGraphic(size, size, FlxColor.YELLOW);
    FlxG.state.add(self);
}

function update(self, elapsed) {
    self.angle += elapsed * 120;
}
createScripted('Spinner', 'spin', 800, 280, 120)   -- Lua: the HScript class works the same way

Global scripts & variables Vortex

states/Global.lua (or .hx) runs in every menu and custom state, right before the screen's own state script. Use getStateName() to react to specific screens. For songs, keep using scripts/.

function onCreatePost()
    setGlobalVar('screensVisited', getGlobalVar('screensVisited', 0) + 1)
    if getStateName() == 'MainMenuState' then
        debugPrint('Screens visited: ' .. getGlobalVar('screensVisited'))
    end
end

Global variables keep their value when the screen changes and between songs, for the whole session. They're not saved to disk; use initSaveData for that. setVar / getVar still work as in Psych and are cleared on every screen change.

FunctionDescription
setGlobalVar(name, value)Stores a value. Returns it.
getGlobalVar(name, default?)The value, or default (or nil) if it was never set.
globalVarExists(name)true if it was set.
removeGlobalVar(name)Forgets it.

Shared code with require() Vortex

Put code you use in several scripts in lib/ and load it with Lua's normal require. Files in lib/ never run by themselves.

local M = {}
function M.double(x) return x * 2 end
return M
local mathutil = require('mathutil')
debugPrint(mathutil.double(21))   -- 42

require('name') looks in this order: mods/<your mod>/lib/name.lua, mods/<your mod>/lib/name/init.lua, mods/lib/name.lua, the script's own folder, then Lua's usual places. Each script gets its own copy of a module, loaded once.

Custom substates Vortex

Psych's openCustomSubstate (a screen on top of the current one, like a popup) now works in menus and custom states too, not only in songs. The current screen's scripts get its callbacks.

local frame = 0
function onUpdate(elapsed)
    frame = frame + 1
    if frame == 2 then openCustomSubstate('info') end   -- after the screen's fade-in has started
end

function onCustomSubstateCreate(name)
    makeLuaText('infoText', 'Press ENTER to close', 600, 340, 340)
    addLuaText('infoText')
    insertToCustomSubstate('infoText')
end

function onCustomSubstateUpdate(name, elapsed)
    if keyboardJustPressed('ENTER') then closeCustomSubstate() end
end
Don't open a substate from onCreate: the screen's fade-in transition opens right after and replaces it. Open it on a later frame, as above, or from input.

HScript (.hx)

Any script above can be written in HScript (Haxe syntax) by using .hx instead of .lua. HScript has direct access to Flixel and engine classes (FlxG, FlxSprite, FlxTween, Paths...), as in Psych Engine 1.0.

The new Vortex functions are available in HScript too. There, arguments are passed as an array:

switchState('Gallery', ['hello', 42]);
var spr = createScripted('Bouncer', 'red', 300, 300, ['FF4F7A']);  // returns the sprite
callScripted('red', 'jump', [120]);
var sameSprite = getScripted('red');
var args = getStateArgs();

Achievement Editor Vortex

Make achievements for your mod without writing JSON by hand: a name, a description, an icon, an ID, when it unlocks, and an optional Lua script. They show up in the game's Achievements menu and pop up when unlocked, like the built-in ones, and progress is saved.

  1. On the main menu press 7 to open the Developer menu.
  2. Pick your mod with Left / Right (the bar at the bottom shows the loaded mod folder).
  3. Choose Achievement Editor (the last entry) with Enter or the mouse.

The editor saves into mods/<your mod>/achievements/, or mods/achievements/ with no mod selected. The left side shows a live preview card (icon, name, description, locked / unlocked, progress) and every achievement in that folder. The right side has three tabs:

TabFields
AchievementLoad from this folder; ID (also the file name: lowercase letters, numbers, - and _; the editor refuses an ID another mod already uses); Name; Description; Icon file (a PNG in the same folder, empty = <id>.png); Hidden until unlocked; Progress goal (0 = none, e.g. 5 = "finish 5 songs"). Buttons: New, Save, Test Popup, Reset Progress (relocks it in your own save, for testing).
UnlockUnlock when: manual, song_complete or week_complete; Song; Week file; Max misses (-1 = any); Min accuracy %; Min score; Practice Mode counts too.
ScriptShows whether the achievement has a script and the functions it can use. Create Lua script / Create HScript write a working example you can edit.

When achievements unlock

Unlock typeUnlocks when
manualOnly a script unlocks it: unlockAchievement(id) (or addAchievementScore with a progress goal).
song_completeA song is finished. song empty = any song; names are matched like song folders, so Example Song and example-song are the same.
week_completeThe last song of the week week (its week file name) is finished in Story Mode. Max misses and Min score count the whole week.
  • Conditions are checked when a song ends. Botplay and the Chart Editor never unlock achievements, and Practice Mode only counts with Practice Mode counts too on.
  • With a Progress goal, every finish that meets the conditions adds 1, and the achievement unlocks at the goal. The Achievements menu shows the progress.
  • Unlocks and progress are saved in the player's save file straight away, under the achievement's ID.
  • Psych Engine's way still works unchanged: data/achievements.json with icons in images/achievements/<save>.png.

Achievement files Vortex

The editor writes plain files, so you can also make or edit them by hand. Each achievement is up to three files with the same name, its ID:

mods/My-Mod/achievements/ ├─ first-steps.json name, description, unlock condition ├─ first-steps.png icon (optional; 150×150 looks best) ├─ combo-starter.json ├─ combo-starter.png └─ combo-starter.lua script, optional (or .hx)
{

	"description": "Finish the Example Song.",
	"hidden": false,
	"unlock": {
		"type": "song_complete",
		"song": "example-song",
		"maxMisses": -1,
		"minAccuracy": 0,

FieldMeaning
name, descriptionShown in the popup and the Achievements menu.

iconOptional PNG file name in this folder. Without it, <id>.png is used, then Psych's images/achievements/<id>.png.

Achievements from every enabled mod are loaded. If two use the same ID, the first one is kept and the other is reported in vortex_script_log.txt.

Achievement scripts Vortex

For conditions the Unlock tab can't express (a combo, a secret, a mechanic), attach a script. achievements/<id>.lua runs in every song while the achievement is still locked, and it doesn't load at all once it's unlocked. It can use every normal song callback and function, plus the variable achievementId.

-- Attached to the achievement "combo-starter" (same file name as combo-starter.json).
-- It runs in every song while the achievement is still locked; achievementId is "combo-starter".

function goodNoteHit(id, direction, noteType, isSustain)
    if botPlay then return end -- botplay shouldn't earn achievements
    if getProperty('combo') >= 20 then
        unlockAchievement(achievementId)
    end
end

Strumlines Vortex

A strumline is a row of 4 arrows with its own notes and its own characters, like in Codename Engine. A song can have up to 8. Use them for duets, a third singer, backup singers, or two players' worth of notes.

Every song starts with the two Psych rows: strumline 1 is the player (boyfriend) and strumline 2 is the opponent (dad). Charts made in Psych Engine have exactly these two and play the same as before; nothing is added to them unless you add a strumline.

TypeWho hits its notes
playerYou. Its notes count for score, health, combo and misses, like boyfriend's.
opponentThe CPU, like dad's notes.
additionalThe CPU too, but it never moves the camera or touches the opponent's vocals. Meant for backup singers.

In the Chart Editor

  • The grid shows one group of 4 columns per strumline, with the main singer's icon above it.
  • To choose who sings a note, select it and use Sung by in the Note tab. A note sung by one singer gets a small S1, S2... badge. A note without a badge is sung by every singer of its strumline.
  • Strumlines themselves (how many, their type, singers and arrow position) are set in the chart file, below. The Strumlines menu that 0.4 had in the editor's top bar was removed in 0.5.

In the chart file

Strumlines are the strumLines list in the chart (the editor keeps it when it saves). Strumline 3 uses columns 8-11, strumline 4 uses 12-15, and so on. A note's 5th value is its singer (0 = first); leave it out, or use -1, for all singers.

"strumLines": [
    {"name": "Player", "type": "player", "characters": [{"name": "bf"}, {"name": "pico", "position": "boyfriend", "x": 260}]},
    {"name": "Opponent", "type": "opponent", "characters": [{"name": "dad"}]},
    {"name": "Backup", "type": "additional", "strumScale": 0.5,
     "characters": [{"name": "spooky", "position": "gf", "x": -300, "flipX": true}]}
],
"notes": [{"sectionNotes": [
    [2400, 0, 0, "", 1],
    [4800, 9, 0]
]}]
  • The first note (column 0, 5th value 1) is on strumline 1 and only pico sings it. The second (column 9) is on strumline 3, sung by everyone on it.
  • For strumlines 1 and 2 the first character is always the song's player 1 / player 2, so Change Character events keep working.
  • Other fields: visible, strumX / strumY (screen position of the left arrow; leave them out for automatic) and strumScale (1 = normal size; extra strumlines default to 0.5).
  • Extra singers are in game.variables as strumLine2_char0, strumLine0_char1... so playAnim, setProperty and friends work on them.
  • Notes for a strumline the chart doesn't define are skipped and reported once in vortex_script_log.txt.
  • Known limit: the Chart Editor's own test-play (Enter in the editor) shows extra strumlines' notes on the opponent's side. Play the song normally to see them.

Strumline functions Vortex

Put a mod made for another engine in mods/, enable it, and Vortex works out which engine it was made for and translates what it can into its own (Psych Engine) format.

  • Every translated mod gets a report: vortex_compat/<mod>/report.txt (what was converted, what was approximated, errors, and what needs manual changes). vortex_compat_log.txt has one line per mod. You can also read it in the game: Developer menu → V-Slice Converter → R.

  • Mods don't all keep their files in the same place. V-Slice Converter Vortex

Developer menu (7 on the main menu) → V-Slice Converter. It copies a mod into V-Slice's folder layout so you can start porting it to V-Slice.

  1. Pick the mod on the left. The right side shows which engine it was made for and what Vortex found in it (R shows the full compatibility report).
  2. Press ENTER. The result goes to vortex_converted/<mod>-vslice/ next to the game. The mod itself is not changed. Converting again replaces only a folder the converter made; any other folder with that name is kept and the output goes to -vslice-2.
  3. Read REPORT.txt in the output (V shows it, O opens the folder).
  4. 0.7 The zip vortex_converted/<mod>-vslice.zip is made every time (Z makes it again). It has the mod folder at the top, so unzipping it inside V-Slice's mods/ folder puts it at the right depth: mods/<mod>-vslice/_polymod_meta.json. On a phone, that mods/ folder is in FNF's folder in your files app. Restart the game after adding a mod.
Mod not showing up in V-Slice? V-Slice only looks one folder into mods/ and skips anything deeper without a message. mods/vortex_converted/My-Mod-vslice/ (zipping the whole vortex_converted folder) or mods/My-Mod-vslice/My-Mod-vslice/ (some unzip apps add a folder) won't load: move the folder that has _polymod_meta.json in it directly into mods/.
vortex_converted/My-Mod-vslice/ ├─ _polymod_meta.json ├─ data/songs/<song>/<song>-metadata.json name, BPM changes, characters, stage, difficulties ├─ data/songs/<song>/<song>-chart.json notes per difficulty, scroll speeds, events ├─ data/characters/ data/stages/ data/levels/ ├─ songs/<song>/Inst.ogg, Voices-<character>.ogg ├─ images/ sounds/ music/ shaders/ videos/ └─ REPORT.txt
  • Converted: charts (every difficulty file the song has), BPM changes, section cameras (as FocusCamera), Play Animation, Hey!, Change Scroll Speed, Focus Camera and Zoom Camera events, characters, stages with objects, weeks (as levels), audio and pictures.
  • 0.7 Characters stand exactly where they do in Psych. V-Slice places a character by its feet and its idle pose; the converter works out each character's offsets from its sprite sheet so the result matches Psych, camera included. Psych's default stage (stage) is written as a stage too, so songs on it line up.
  • 0.7 Nothing replaces the base game. A character, stage, song or week whose id is already in V-Slice's base game (like bf, gf, bf-dark, mainStage, week1) is renamed <id>-<your mod>: the same id would replace the base one everywhere and run its script (which crashes with "Render type mismatch"). Base-game characters your songs use are copied in under the new name, with their pictures.
  • 0.7 Lua scripts are translated to V-Slice HScript: custom_events/<name>.lua becomes a V-Slice event (scripts/events/), song scripts (data/<song>/*.lua) and global scripts (scripts/*.lua) become V-Slice modules that run in their song / in all of your songs. Psych's callbacks (onCreatePost, onUpdate(Post), onBeatHit, onStepHit, goodNoteHit, opponentNoteHit, noteMiss, onEvent, onSongStart, onEndSong, onTimerCompleted, onTweenCompleted) and the common Psych functions (getProperty / setProperty with Psych's numbers for character positions and the camera, cameraFlash, cameraShake, doTweenZoom, doTween…, makeLuaSprite, makeGraphic, addLuaSprite, runTimer, triggerEvent, setCameraFollowPoint, getMidpointX/Y, playSound, playAnim, mustHitSection…) are rebuilt with V-Slice's classes. Psych's built-in Add Camera Zoom, Screen Shake, Camera Follow Pos, Change Character, Set GF Speed, Alt Idle Animation, Play Sound and Set Property events work the same way. A Psych function with no V-Slice version is listed in the report and only prints a message; a callback that hits something V-Slice doesn't have stops quietly instead of showing an error every frame.
  • 0.7 Dialogue: a startDialogue('file') in a song's Lua becomes a V-Slice conversation: the lines, the portraits (placed where Psych puts them) and Psych's speech bubble. It plays before the countdown (only in Story Mode if your Lua checked isStoryMode) or after the song if it was in onEndSong.
  • 0.7 Phones: picture names get their real upper / lower case (phones care, Windows doesn't). 0.7.1 Character and stage pictures bigger than 4096 pixels are made smaller (an 8192×8192 picture uses 256 MB of video memory and makes phones lag); the sprite is drawn bigger by the same amount, so it looks the same. A picture whose path the base game also uses (for example characters/DADDY_DEAREST) goes to images/<your mod>/, so it doesn't replace the base game's picture in every song.
  • 0.7.2 Dialogue, videos and HUD: the converted dialogue box draws its text with Psych's alphabet letters, placed like Psych's dialogue box; portraits use the offsets Psych uses for the animation they show; a portrait the mod doesn't include comes from Psych's own (or bf, like Psych). A startVideo() before the countdown or in onEndSong plays the video with V-Slice's video player (videos are written to videos/videos/, where V-Slice looks). Lua sprites and texts on the HUD are drawn over the HUD like in Psych, except a sprite covering most of the screen, which goes just under the notes so they stay visible on phones.
  • 0.7.1 Speed: V-Slice runs scripts through an interpreter, which is slow on phones. Translated scripts only do Lua's text-to-number conversion where Psych passes text (event values), read table fields directly, and only hook the callbacks they use. A heavy per-frame Lua script still costs frames on a phone: if a mod lags, the report's list of converted scripts is the place to look.
  • Not converted, and listed in the report: Psych HScript (.hx), events with no script, notes on extra strumlines, which singer sings a note, Story Mode menu characters, note types, achievements, custom menus, shaders set up from Lua, Lua that uses Psych functions with no V-Slice version (listed by name).
  • Every written file is read back and checked (valid JSON, every difficulty has notes and a scroll speed, notes in lanes 0-7).
  • _polymod_meta.json gets "api_version": "0.8.0". V-Slice 0.8.x has no mod list: it loads every folder in its mods/ whose api_version is in its range (>=0.8.0 <0.9.0), so the converted mod is on as soon as it's there. For another V-Slice version, change the number to that version.
  • Tested in the official Friday Night Funkin' 0.8.6 (Windows) with a real Psych mod: character placement, renamed characters, custom events, Change Character, song and global scripts (camera, zoom) and dialogue. Play your songs in V-Slice before releasing: a translated script can still behave differently where Psych and V-Slice work differently.
iOS: not verified. The converter does nothing iOS-specific. Running a mod on iOS needs a V-Slice build for iOS that includes it (usually built from source on a Mac with Xcode), no Lua, ported HScript, shaders that compile as GLSL ES, H.264 .mp4 videos and no Windows-only code. Test on a real device.

Notes from scripts Vortex

spawnNote adds a note while the song is playing, for mechanics that aren't in the chart: random notes, patterns generated from code, notes made by an event. It's built exactly like a chart note, holds included.

function onSongStart()
    local t = getSongPosition()
    -- spawnNote(time in ms, column 0-3, mustPress, noteType, holdLength in ms)
    spawnNote(t + 1500, 1, true, 'Bonus Note')     -- a Down note for the player, 1.5 s from now
    spawnNote(t + 1900, 2, true, '', 300)          -- an Up note with a 300 ms hold
    spawnNote(t + 2400, 0, false)                  -- a Left note for the opponent
end
  • noteType can be any custom note type. Its custom_notetypes/<Type>.lua (or .hx) script is loaded the first time a note of that type is spawned, even if the chart never uses it. goodNoteHit, noteMiss, onSpawnNote and so on work on these notes like on chart notes.
  • Returns true when the note was added. It only works during a song; elsewhere it returns false and prints a message.
  • A note whose time has already passed counts as a miss, as in a chart.
function goodNoteHit(id, direction, noteType, isSustain)
    if noteType == 'Bonus Note' then
        addScore(500)
    end
end

Custom events

Events are things that happen at a set time in the chart. Make your own in custom_events/.

custom_events/ ├─ Flash Test.txt description shown in the chart editor (optional in Vortex) └─ Flash Test.lua or Flash Test.hx
function onEvent(name, value1, value2, strumTime)
    if name == 'Flash Test' then
        cameraFlash('game', 'FFFFFF', 0.5)
        debugPrint('Flash Test fired, value 1 = ' .. value1)
    end
end
  • In the chart editor, pick the event in the Events tab, fill in Value 1 and Value 2, and place it on the grid.
  • Vortex An event with only a .lua or .hx file and no .txt still shows up in the chart editor list. Psych only listed events that had a .txt.
  • Vortex You can fire an event from any script, even one that isn't placed in the chart. The engine loads its script the first time: 
    triggerEvent('Flash Test', 'hello', '')
    In Psych, an event that wasn't in the chart never loaded its script, so onEvent never reached it.
  • onEventPushed(name, value1, value2, strumTime) runs once for every event in the chart while the song loads. It's useful for preloading.

Change Stage event Vortex

A built-in event that swaps the whole stage in the middle of a song. It works with your own stages and with the built-in ones.

ValueWhat to write
Value 1The stage you're in now, e.g. stage.
Value 2The stage to change to: a stage from stages/<name>.json or a built-in one.

The characters stay and move to the new stage's positions. The camera zoom and offsets change to the new stage's, and the new stage's script (stages/<name>.lua or .hx) is started. The old stage's script keeps running, so check curStage in it if it should stop doing things. The new stage's pictures are loaded while the song loads, so the swap doesn't stutter. If Value 1 doesn't match the current stage, the stage changes anyway and a note goes to the log.

triggerEvent('Change Stage', 'stage', 'my-night-stage')   -- from a script

Official builds Vortex

Official Vortex Engine release zips contain a signed list of the game's files. Every time it starts, the game checks it in the background.

ResultMeaning
Verifiedvortex_manifest.json is signed with the release key and every program and asset file matches it.
UnverifiedNo signed manifest (every build made from the source code, including GitHub Actions builds), a signature that doesn't match, or a manifest for another version. This does not mean the build is harmful.
Integrity check failedThe signature is valid but files were changed or removed, or extra program files (.exe / .dll / .ndll) were added next to the game. The message names them.
  • When the build isn't verified, the game writes UNOFFICIAL_BUILD_README.txt next to the executable: the version, when it was built, the result and where to get official releases (github.com/burgergoose/vortex-engine). It is only rewritten when its text changes, an unrelated file with that name is never overwritten, and it is removed when the build checks out as official again. If the game folder can't be written to, it goes to the game's data folder (%APPDATA%\Vortex Engine\VortexEngine\ on Windows) and a message says where.
  • Mods, logs, modsList.txt and the translation / converter folders are not part of the check, so adding mods never affects it.
  • The F3 overlay shows the result (Build: ...).
  • Limits: this can't guarantee a copy is safe. Someone who changes the executable itself can also remove or fake the check. Only download the game from the official page.
  • For maintainers: tools/sign_release.py signs a release folder with the private key, which is kept outside the repository and never shipped. The executable only contains the public key.

Troubleshooting

  • "A mod from V-Slice / Codename shows up but plays wrong." Open vortex_compat/<mod>/report.txt (or Developer menu → V-Slice Converter → R). Scripts and custom events of other engines don't run in Vortex; the report lists each one.
  • "A V-Slice mod's stage is black." Its pictures are made by a stage script. Since 0.6 Vortex reads the sprites out of scripts/stages/; the report lists anything it left out (sprites that start hidden, sprites on the HUD, things the script does during the song).
  • "I can't switch my mod on in the base game (V-Slice 0.8)." V-Slice 0.8 has no Mods menu: it loads every mod folder in its mods/ whose _polymod_meta.json has an api_version in its range (0.8.0 to below 0.9.0). Mods made with the V-Slice Converter get 0.8.0.
  • "Tutorial and Week 1 stay in Story Mode after I deleted them." Deleting them from the source assets/ doesn't remove the copy already in the built game, and weekList.txt only sets the order. Use "hideBaseGameWeeks" in your mod's pack.json (see Setting up a mod).
  • "My mod's songs don't appear after I changed its files." The translation is redone when files in data/, scripts/ or songs/ change. If it still looks old, delete vortex_compat/<mod>/ (it is made again).
  • "My custom menu isn't used." The Menu Editor lists what's wrong with menu.json under the preview. Until it is fixed, the built-in theme is used.
  • "There's an UNOFFICIAL_BUILD_README.txt next to the game." You are running a build that isn't a verified official release (for example one you built yourself). It's safe to delete; see Official builds.
  • "My Camera Flash event doesn't flash." Check Options → Visuals → Flashing Lights: when it's off, flashes are skipped on purpose, and a script that checks flashingLights before calling cameraFlash does nothing. Vortex and Psych Engine keep separate settings, so it can be on in one and off in the other. Since 0.4, camOther / camHUD / camGame exist in Lua and durations can be strings.
  • "Story Mode shows a week named after my mod." Fixed in 0.4. Songs that aren't in any week get an automatic week, but only in Freeplay. Songs in a hidden week (hideStoryMode) stay out of Story Mode too.
  • "The Week Editor saved a file without .json." Fixed in 0.4. It now saves straight to mods/<your mod>/weeks/<name>.json and says where.
  • "My event doesn't do anything." Check that the name in if name == '...' matches the file name exactly, spaces included. Check vortex_script_log.txt for script errors.
  • "My custom state isn't found." The file must be in states/ inside an enabled mod, and switchState takes the file name without .lua.
  • "createScripted returns nil." The class file isn't in classes/, or its new function has an error. Check vortex_script_log.txt.
  • "The vocals went silent after I paused the song." Fixed in 0.3. In Psych Engine 1.0, resuming checked both vocal tracks against the player track's length, so in songs with only opponent vocals, or a shorter player track, the opponent vocals stopped for the rest of the song. An empty vocal track could also be reused for menu sounds. Each track is now checked on its own, and a playing track that drifts more than 40 ms from the instrumental is moved back.
  • "My achievement doesn't unlock." Botplay, the Chart Editor and (unless allowed) Practice Mode never unlock achievements. Check that the mod is enabled, the ID is unique, and look in vortex_script_log.txt. Reset Progress in the Achievement Editor relocks one to test it again.
  • "The game is stuck on the Now Loading screen." This was a threading bug in Psych Engine 1.0's loader: two files finishing at the same moment could lose count. It's fixed in Vortex. If it still happens, send the newest file in crash/ and vortex_script_log.txt.
  • "require can't find my module." It must be in lib/ of an enabled mod (or mods/lib/), and you pass the name without .lua: require('mathutil').
  • "My song doesn't show up." Open vortex_mods_log.txt. It shows whether the mod is on and whether the chart and Inst were found.
  • "Lua functions named createInstance / callMethod behave differently." Those are Psych's Haxe-class functions and are unchanged. Vortex's scripted-class functions are named createScripted / callScripted so they don't clash.
