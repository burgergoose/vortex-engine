Vortex Engine modding

Vortex Engine is built on Psych Engine 1.0, so Psych Lua and HScript mods keep working. On top of that it adds custom screens, reusable scripted objects and scripts for the built-in menus, so you can build bigger mods without touching the engine's Haxe source.

Custom states Scripted classes State scripts Lua outside songs Change Stage event Psych 1.0 compatible

Everything on this page is implemented in the engine as it ships. Anything marked Psych works the same way as in Psych Engine, and the Psych Engine wiki has the full list of its standard Lua functions. Anything marked Vortex is new in Vortex Engine and documented in full here.

Setting up a mod

A mod is a folder inside mods/, next to VortexEngine.exe. Create a folder for your mod and add only the subfolders you need.

mods/ └─ My-Mod/ ├─ pack.json name, description, "runsGlobally" ├─ weeks/ week files (optional, see below) ├─ data/<song>/ charts + song scripts ├─ songs/<song>/ Inst.ogg, Voices.ogg ... ├─ characters/ stages/ images/ sounds/ music/ ├─ scripts/ Lua/HScript that runs in every song ├─ custom_events/ your chart events ├─ custom_notetypes/ ├─ states/ Vortex: custom states + menu scripts └─ classes/ Vortex: scripted classes
  • Mods are switched on and off in the Mods menu. A new folder is switched on automatically.
  • Songs without a week: a song that has a chart in data/<song>/ but isn't in any week file still shows up in Freeplay and Story Mode, in an automatic week named after the mod.
  • When you start the game, Vortex writes vortex_mods_log.txt next to the exe. It lists every mod, whether it's on, how many songs, characters, stages and events it has, and whether each song's Inst file was found.

Where scripts go

Every script can be Lua (.lua) or HScript (.hx). Where you put the file decides when it runs.

Path in your modRuns
scripts/*.luaIn every songPsych
data/<song>/*.luaIn that song onlyPsych
stages/<stage>.luaWhen that stage is usedPsych
characters/<name>.luaWhen that character is in the songPsych
custom_events/<Event>.luaWhen the event is in the chart, or the first time a script fires itPsych Vortex
custom_notetypes/<Type>.luaWhen the chart uses that note typePsych
states/<BuiltInState>.luaAlongside a built-in screen, e.g. states/MainMenuState.luaVortex
states/<YourState>.luaAs a whole screen, opened with switchState('YourState')Vortex
classes/<Class>.luaWhen you create an object from it with createScriptedVortex
Which mod's files are used? In songs, it's the mod the song belongs to, plus any mods with "runsGlobally": true in their pack.json. For states/ and classes/, Vortex looks in every enabled mod (the current one first). That's because in menus only the top mod is "current".

Debugging

  • debugPrint('text') shows a message on screen. It now works everywhere: in songs, in menus and in custom states. Outside songs the messages appear top-left and fade after about 6 seconds.
  • Put luaDebugMode = true at the top of a Lua script to see its errors on screen, for example a typo in a function name. Psych hides these by default.
  • If the game hits an error it can't handle, it goes back to the main menu and shows a red message instead of closing. Full details go to the crash/ folder next to the exe.

Lua API

All of Psych Engine 1.0's Lua functions are available and behave the same, including Psych's own createInstance and callMethod for Haxe classes. Vortex changes what's described below.

Lua now runs outside songs Vortex

In Psych, Lua scripts only exist during a song. In Vortex, the same Lua runs in menus, custom states and scripted classes. These functions work everywhere:

  • Sprites and text: makeLuaSprite, makeAnimatedLuaSprite, makeGraphic, addLuaSprite, removeLuaSprite, makeLuaText, addLuaText, setTextString, setTextColor, setTextSize and the others.
  • Properties: getProperty and setProperty, including the 'tag.scale.x' style.
  • Tweens, timers and sounds: doTweenX and friends, runTimer, playSound, playMusic. Their onTweenCompleted, onTimerCompleted and onSoundFinished callbacks reach the scripts of whatever screen is running.
  • Input: keyboardJustPressed, keyboardPressed, the gamepad functions and mouseClicked.
  • debugPrint, getModSetting.

Song-only functions such as characterDance, setHealth or note functions still need a song. In a menu they fail with a Lua error instead of crashing the game (turn on luaDebugMode to see it).

addLuaSprite(tag, false) normally places the sprite behind the characters. Outside a song there are no characters, so the sprite is simply added on top.

New functions Vortex

Custom states, state switching and scripted classes each have their own section below. The function reference lists every new function in one table.

Custom states Vortex

A custom state is a whole screen made from one script, such as a gallery, a sound test, a cutscene menu or a minigame. Put it in states/<Name>.lua (or .hx) and open it from any script.

function onCreate()
    makeLuaSprite('bg', '', 0, 0)
    makeGraphic('bg', 1280, 720, '120C24')
    addLuaSprite('bg')

    makeLuaText('title', 'GALLERY', 1280, 0, 40)
    setTextSize('title', 40)
    addLuaText('title')

    local args = getStateArgs()          -- whatever switchState() passed
    debugPrint('opened with: ' .. tostring(args[1]))
end

function onUpdate(elapsed)
    if keyboardJustPressed('ESCAPE') then
        switchState('MainMenuState')     -- back to a built-in screen
    end
end

Open it from anywhere, whether a song script, an event, a menu script or another custom state:

switchState('Gallery')                         -- no arguments
switchState('Gallery', {'hello', 42})          -- arguments, read with getStateArgs()

Callbacks

FunctionWhen
onCreate()When the screen opens.
onCreatePost()On the first frame, after everything is created.
onUpdate(elapsed)Every frame, before the screen updates.
onUpdatePost(elapsed)Every frame, after the screen updates.
onDestroy()When leaving the screen.
onTimerCompleted, onTweenCompleted, onSoundFinishedSame as in songs.

Opening built-in screens

switchState also opens the engine's own screens by name: MainMenuState, FreeplayState, StoryMenuState, OptionsState, CreditsState, TitleState and ModsMenuState. If your mod has a custom state with the same name, yours is opened instead. Switching away from a song stops its music, like "Exit to menu" does.

If nothing has that name, switchState returns false, prints a message and stays on the current screen. It never leaves you on a black screen.

State scripts (scripting the built-in menus) Vortex

Give a script the name of a built-in screen and it runs alongside that screen. The screen keeps working normally, and your script can add things to it. This is how you add a way into your custom states.

function onCreatePost()
    makeLuaText('hint', 'Press G for the gallery', 600, 660, 660)
    addLuaText('hint')
end

function onUpdate(elapsed)
    if keyboardJustPressed('G') then
        switchState('Gallery')
    end
end

The callbacks are the same as for custom states. Use onCreatePost to draw on top of the screen's own graphics. The file name must match the screen's name, for example MainMenuState, FreeplayState, StoryMenuState, CreditsState or TitleState. Songs don't use this: during a song, use scripts/ or data/<song>/ as in Psych.

Scripted classes Vortex

A scripted class is a reusable object written once in classes/<Name>.lua (or .hx). You can create as many copies ("instances") of it as you want, in songs, menus or custom states. Each instance is a normal sprite saved under its tag, so every sprite function works on it.

-- "self" is the instance's tag, so use it like any sprite tag
local timeAlive = {}

function new(self, color)
    makeGraphic(self, 120, 120, color or 'FFFFFF')
    addLuaSprite(self, true)
    timeAlive[self] = 0
end

function update(self, elapsed)
    timeAlive[self] = timeAlive[self] + elapsed
    setProperty(self .. '.y', 300 + math.sin(timeAlive[self] * 3) * 60)
end

function jump(self, height)          -- your own method
    setProperty(self .. '.scale.x', 1.5)
    setProperty(self .. '.scale.y', 1.5)
    return 'jumped ' .. height
end

Use it from any script:

createScripted('Bouncer', 'red', 300, 300, 'FF4F7A')    -- class, tag, x, y, then up to 5 values for new()
createScripted('Bouncer', 'teal', 500, 300, '35D0C0')

local result = callScripted('teal', 'jump', 120)       -- call your own method, get its return value
setProperty('red.alpha', 0.5)                          -- instances are normal sprites

if scriptedExists('red') then destroyScripted('red') end

Class functions

All of these are optional. The instance always comes first. In Lua that's its tag; in HScript it's the sprite itself.

FunctionWhen
new(self, ...)When createScripted makes the instance. It receives the extra values you passed.
update(self, elapsed)Every frame.
beatHit(self, beat)Every beat, while music is driving the beat clock (in songs).
stepHit(self, step)Every step, under the same conditions.
destroy(self)When destroyScripted removes the instance.
anything elseCalled with callScripted(tag, 'name', ...).
  • Each class script is loaded once per screen and shared by all its instances. Lua variables at the top of the file are shared too, so store per-instance data in a table keyed by self, as above.
  • new doesn't add the sprite to the screen by itself. Call addLuaSprite(self, true) (Lua) or FlxG.state.add(self) (HScript) when you want it shown.
  • Instances are cleared when the screen changes. Removing one with removeLuaSprite(tag, true) also stops its update.

HScript class

function new(self, size) {
    self.makeGraphic(size, size, FlxColor.YELLOW);
    FlxG.state.add(self);
}

function update(self, elapsed) {
    self.angle += elapsed * 120;
}
createScripted('Spinner', 'spin', 800, 280, 120)   -- Lua: the HScript class works the same way

HScript (.hx)

Any script above can be written in HScript (Haxe syntax) by using .hx instead of .lua. HScript has direct access to Flixel and engine classes (FlxG, FlxSprite, FlxTween, Paths...), as in Psych Engine 1.0.

The new Vortex functions are available in HScript too. There, arguments are passed as an array:

switchState('Gallery', ['hello', 42]);
var spr = createScripted('Bouncer', 'red', 300, 300, ['FF4F7A']);  // returns the sprite
callScripted('red', 'jump', [120]);
var sameSprite = getScripted('red');
var args = getStateArgs();

Custom events

Events are things that happen at a set time in the chart. Make your own in custom_events/.

custom_events/ ├─ Flash Test.txt description shown in the chart editor (optional in Vortex) └─ Flash Test.lua or Flash Test.hx
function onEvent(name, value1, value2, strumTime)
    if name == 'Flash Test' then
        cameraFlash('game', 'FFFFFF', 0.5)
        debugPrint('Flash Test fired, value 1 = ' .. value1)
    end
end
  • In the chart editor, pick the event in the Events tab, fill in Value 1 and Value 2, and place it on the grid.
  • Vortex An event with only a .lua or .hx file and no .txt still shows up in the chart editor list. Psych only listed events that had a .txt.
  • Vortex You can fire an event from any script, even one that isn't placed in the chart. The engine loads its script the first time: 
    triggerEvent('Flash Test', 'hello', '')
    In Psych, an event that wasn't in the chart never loaded its script, so onEvent never reached it.
  • onEventPushed(name, value1, value2, strumTime) runs once for every event in the chart while the song loads. It's useful for preloading.

Change Stage event Vortex

A built-in event that swaps the whole stage in the middle of a song. It works with your own stages and with the built-in ones.

ValueWhat to write
Value 1The stage you're in now, e.g. stage.
Value 2The stage to change to: a stage from stages/<name>.json or a built-in one.

The characters stay and move to the new stage's positions. The camera zoom and offsets change to the new stage's, and the new stage's script (stages/<name>.lua or .hx) is started. The old stage's script keeps running, so check curStage in it if it should stop doing things. The new stage's pictures are loaded while the song loads, so the swap doesn't stutter. If Value 1 doesn't match the current stage, the stage changes anyway and a note goes to the log.

triggerEvent('Change Stage', 'stage', 'my-night-stage')   -- from a script

Song audio files

Put the audio in songs/<song>/, using the same names as Psych Engine.

FileUsed for
Inst.oggThe instrumental. Required.
Voices.oggAll vocals in one file.
Voices-Player.ogg + Voices-Opponent.oggSeparate vocals for each side.

.wav also works if there's no .ogg. .mp3 does not. If the Inst is missing, Vortex shows a screen saying where it looked, instead of playing a short beep.

Full example

A main-menu entry that opens a custom state full of scripted objects. These are the same files used to test this feature in the engine.

1. Entry point

states/MainMenuState.lua adds a hint and opens the gallery when G is pressed. See State scripts.

2. The screen

states/Gallery.lua is shown below.

3. A Lua class

classes/Bouncer.lua. See Scripted classes.

4. An HScript class

classes/Spinner.hx. See Scripted classes.

function onCreate()
    makeLuaSprite('bg', '', 0, 0)
    makeGraphic('bg', 1280, 720, '120C24')
    addLuaSprite('bg')

    makeLuaText('title', 'GALLERY', 1280, 0, 40)
    setTextSize('title', 40)
    setTextColor('title', '52E7FF')
    addLuaText('title')

    createScripted('Bouncer', 'red', 300, 300, 'FF4F7A')
    createScripted('Bouncer', 'teal', 500, 300, '35D0C0')
    createScripted('Spinner', 'spin', 800, 280, 120)

    runTimer('hello', 1)
end

function onTimerCompleted(tag)
    if tag == 'hello' then
        callScripted('teal', 'jump', 120)
    end
end

function onUpdate(elapsed)
    if keyboardJustPressed('ESCAPE') then
        switchState('MainMenuState')
    end
end

Troubleshooting

  • "My event doesn't do anything." Check that the name in if name == '...' matches the file name exactly, spaces included. Add luaDebugMode = true to see script errors.
  • "My custom state isn't found." The file must be in states/ inside an enabled mod, and switchState takes the file name without .lua.
  • "createScripted returns nil." The class file isn't in classes/, or its new function has an error. Use luaDebugMode = true in the class file.
  • "My song doesn't show up." Open vortex_mods_log.txt. It shows whether the mod is on and whether the chart and Inst were found.
  • "Lua functions named createInstance / callMethod behave differently." Those are Psych's Haxe-class functions and are unchanged. Vortex's scripted-class functions are named createScripted / callScripted so they don't clash.
